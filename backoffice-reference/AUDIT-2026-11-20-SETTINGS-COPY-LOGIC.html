5 เรื่องที่สำคัญที่สุด

  1. หน้าสรุปขั้นตอน 6 แสดงข้อมูลผิด ของเรา P0 แถวกลุ่มลูกค้าขึ้น 3 กลุ่มปลอม ("New Customer / Commander / VIP") ตลอด และแถว "มินิเกมส์ที่หักสิทธิ์" ไม่มีชื่อเกม
  2. บันทึกมินิเกมแล้วค่าหาย ของเรา P1 ตอนบันทึกไม่อ่านประเภทยอดฝากจากขั้นตอน 3 และบันทึกลิมิตรางวัลทุกช่องเป็น 0
  3. ฟอร์มภารกิจบันทึกไม่ได้ แต่ไม่บอกว่าผิดตรงไหน ต้นฉบับ P1 แอดมินเห็นแค่ "ทำรายการไม่สำเร็จ ! / กรุณาตรวจสอบข้อมูลภารกิจของคุณ"
  4. คำหรือ error ที่เป็นของช่องอื่น ต้นฉบับ error ชื่อภารกิจย่อยบอกให้กรอกชื่อของรางวัล error ประเภทโบนัสบอกให้เลือกประเภทการฝาก และมีส่วนหนึ่งที่หัวข้อกับตัวเลือกทั้ง 2 อันใช้คำเดียวกัน
  5. ขาดการตรวจค่า ทำให้ข้อมูลผิดผ่านไปได้ ต้นฉบับ P1 เวลาสิ้นสุดก่อนเวลาเริ่มได้ ช่วงวันที่ว่างได้ โอกาสออกรวมกันไม่ต้องได้ 100% เปิดตรวจยอด Balance โดยไม่ใส่ยอดได้

  • Copy-paste key คำแปลข้ามช่อง ก๊อปบล็อกมาแล้วไม่ได้เปลี่ยน key คำหรือ error เลยไปบอกเรื่องของช่องข้างๆ ซึ่งเป็นแบบเดียวกับเรื่องชื่อสีที่แก้ไปวันนี้
  • ไม่มีการตรวจค่า หรือตรวจแต่ไม่บอก ต้นฉบับตรวจแค่ไม่กี่ช่อง ที่เหลือบันทึกค่าว่างหรือค่าขัดกันได้ หรือล็อกปุ่ม "ถัดไป" โดยไม่บอกเหตุผล
  • เรื่องเดียวกันแต่ใช้หลายคำ: มินิเกม/มินิเกมส์, อัพโหลด/อัปโหลด, เทิร์น/เทิร์นโอเวอร์/Turnover, ภารกิจ/มิชชั่น, เรียกวงล้อ 3 แบบ และใช้ "โปรโมชั่น" เรียกตัวมินิเกมเอง
  • จุดที่เราพลาดเองอยู่ในหน้าสรุปและตอนบันทึก (wizard-summary.ts): ช่องที่ไม่มีโค้ดเติมค่า และค่าที่ตอนบันทึกไม่ได้อ่าน

สิ่งที่ทำได้ดี

  • rebuild ลอกต้นฉบับได้ตรง และทุก bug ที่ตั้งใจเก็บไว้หรือจุดที่ทำต่าง มีคอมเมนต์พร้อมเลขบรรทัด ทำให้ตามหาที่มาได้เร็ว
  • th.json ของต้นฉบับมีคำที่ถูกอยู่แล้วหลายคำ (textColor2, chartBorderColor, missionStatusOfflineNew, missionSettingNo) หลายข้อแค่ "เปลี่ยนไปใช้ key ที่ถูก" ก็จบ

สิ่งที่ PK ต้องตัดสินใจก่อนแก้

1 · จะแก้ bug ต้นฉบับแค่ไหนถ้าแก้จะผิดกฎ "ลอกต้นฉบับให้เหมือน" ตัวเลือก: แก้ทั้งหมด · แก้แค่ P1 · แก้แค่คำ และคงตรรกะเดิมไว้ ข้อเสนอ: แก้ P1 ทั้งหมด และแก้คำทั้งหมด
2 · ตกลงคำมาตรฐานเลือกคำเดียวต่อหนึ่งเรื่องก่อน (มินิเกม หรือ มินิเกมส์, อัปโหลด, Turnover, สมาชิก, วงล้อนำโชค, เกมส์อื่น ๆ, ภารกิจ / ภารกิจย่อย) ไม่อย่างนั้นแก้ไปแล้วจะไม่สม่ำเสมอเพิ่มอีก
3 · หน้าสรุปควรแสดงแค่ไหนให้ขั้นตอน 6 แสดงทุกค่าที่ตั้ง หรือคงไว้เหมือนต้นฉบับ
4 · คำถามเรื่องกฎของระบบ"ระหว่างวันที่" เป็นช่วงวันที่ไหม? "ทำเทิร์นติดต่อกัน N ครั้ง" นับอะไร? "Reset" แบบที่ 3 ทำอะไร? ขนาดรูปจริงของข้อ G2 คือเท่าไร?

ลำดับการแก้ที่แนะนำ

  1. ส่วน A (ของเรา) แก้ A1–A4 ก่อน (ข้อมูลผิด) แล้วต่อ A5–A11 ไม่ต้องรอการตัดสินใจ
  2. แก้คำ หลังตกลงคำมาตรฐาน: หัวข้อและ error ที่ผิด คำผิด และคำแปลอังกฤษ
  3. แก้การตรวจค่าและตรรกะ หลังตัดสินเรื่องนโยบาย: G3, G5, G6, S4, S5, S7
  4. ตรวจรอบสุดท้าย แล้ว audit ซ้ำอีกครั้ง
